# 게임 설계서 — 2026 조달청 AI 게임 공모전 출품작

> 이 문서는 PPS-game의 **단일 기준 문서**다. 기능을 만들거나 바꾸기 전에 반드시 이 문서를 확인하고,
> 문서와 다르게 구현해야 할 이유가 생기면 먼저 사용자(인준)에게 묻는다.
> 문서에서 `🔲 미정`으로 표시된 항목은 임의로 결정하지 말고 사용자에게 확인한다.

## 1. 공모전 요구사항 (변경 불가 조건)

- **주제**: 조달청 또는 조달정책 소재
- **마감**: 2026-11-22(일) — 목표 제출일 **11-21(토)**
- **제출물**
  1. 게임 실행파일 ZIP → `AI게임_실행파일_작품명_성명.zip`
  2. 게임 시연영상 1분 내외, 1080p 이상 MP4 → `AI게임_시연영상_작품명_성명.mp4`
  3. 참가신청서 PDF, 개인정보동의서 PDF
- **심사 기준 (100점)**: 독창성 15 · **주제적합성 20** · 완성도 15 · 작품성(재미·영상미·조작 용이성·교육 효과) 15 · **활용도(홍보용 적합) 20** · 대중성(전 연령 이해) 15
- **저작권**: 제3자 권리 침해 시 수상 취소. 사용한 폰트·이미지·음원은 상업적 이용 가능한 것만, 출처는 `CREDITS.md`에 기록.

**설계에 주는 영향**
- 조작은 클릭/터치·드래그만. 튜토리얼 없이도 첫 사업에서 자연스럽게 배우게.
- 정책 용어는 쓰되 반드시 쉬운 말로 풀어서 보여준다 (교육 효과 + 대중성).
- 시연영상에서 돋보일 "도장 쾅" 같은 연출을 우선한다 (영상미 + 활용도).

## 2. 레퍼런스와 표절 방지

- **장르 레퍼런스**: 서류 심사형(inspection) 게임 장르 — Papers, Please 계열의 "서류를 규칙과 대조해 판정"하는 메커니즘을 오마주한다.
- **절대 하지 말 것**
  - 원작 게임의 이름, 고유명사, 대사, UI 레이아웃, 아트 스타일(어두운 픽셀아트), 음악/효과음을 가져오지 않는다.
  - 코드, 화면, 문서 어디에도 원작 게임 이름을 쓰지 않는다. 장르는 "서류 심사형 시뮬레이션"으로 부른다.
- **차별점**
  - 밝은 톤 + 조달청 공식 마스코트 3D 이미지
  - 1명씩 판정하고 끝이 아니라 **걸러내기 → 비교 선택**의 2단계 구조
  - AI 비서 나르미의 힌트 시스템
  - 선택이 1년 뒤 뉴스로 돌아오는 **지연 결과 엔딩**

## 3. 세계관과 캐릭터

| 캐릭터 | 역할 | 비고 |
|---|---|---|
| **달이** (가방 멘 다람쥐) | 플레이어. 조달청에 막 입사한 신입 조달관 | 창구 담당. 성실하지만 아직 서툶 |
| **나르미** (고글 낀 매) | AI 조달 비서. 서류의 수상한 점을 짚어주고 정책을 쉬운 말로 설명 | "AI 활용" 메시지의 중심 |
| 업체 대표들 | 입찰하러 창구에 오는 NPC | 마스코트 아님. CSS로 그린 단순 캐릭터, 업체마다 색만 다르게 (확정) |

**스토리 뼈대**: 달이의 첫 출근(집 → 출근길 → 조달청 → 업무 장소) → 업무 장소 책상 위 컴퓨터에서 사업 폴더를 골라(순서 자유) → 매 사업마다 업체 5곳 심사 → 마지막 사업 후 "1년 후 조달 뉴스"로 그동안의 선택 결과 공개 → 칭호 엔딩.

**마스코트 사용 규칙**
- 조달청이 공모전용으로 제공한 공식 자료만 사용한다 (`assets/img/narmi_3d.png`, `assets/img/dali_3d.png`).
- 원본 디자인을 AI로 재생성·변형하지 않는다. 표정 변화는 말풍선, 이모티콘 효과, 흔들림/확대 애니메이션으로 표현한다.
- 좌우 반전, 크기 조절, 잘라내기는 허용.

## 4. 핵심 게임 루프 (사업 1건)

```
① 사업 공고 도착   — 발주기관, 품목, 수량, 예산 상한, 필수 조건, 마감일
② 업체 5곳 입장    — 한 곳씩 창구에 와서 서류 묶음을 제출
③ 서류 대조        — 공고 조건과 서류를 비교해 문제를 찾는다 (메인 플레이)
④ 판정 도장        — 적격 / 부적격(사유 선택)
⑤ 낙찰 선택        — 적격 2곳 중 1곳을 고른다
⑥ 다음 사업으로    — 결과는 즉시 공개하지 않고 엔딩에서 공개
```

### 4.1 판정 구조 (확정)

- 업체 5곳 = **부적격 3곳 + 적격 2곳** (기본값. 사업별로 데이터에서 조정 가능)
- **걸러내기(③④)는 정답이 있는 퍼즐**: 부적격 업체에는 서류 안에 명확한 근거가 반드시 하나 이상 있다.
- **낙찰(⑤)은 가치 판단**: 적격 2곳은 성격이 정반대이고 **둘 다 정답**이다.
  - 어느 쪽을 골라도 엔딩에서 좋은 결과와 아쉬운 결과가 섞여 나온다.
  - 한쪽이 명백히 우월해 보이면 안 된다 (퀴즈가 되고, "정부가 잘못 골랐다"는 인상을 준다).

### 4.2 판정 실수 처리 (확정 — 제안안)

- 부적격 업체를 적격으로 통과시킴 / 적격 업체를 반려함 → **감사 지적 1회**
- 사유를 틀리게 고름(부적격은 맞지만 이유가 다름) → 지적 없음, 나르미가 정답 사유를 알려줌
- 지적 누적은 엔딩 칭호와 뉴스에 반영 (게임오버 없음 — 전 연령 대상이므로)

## 5. 서류 심사 상세

### 5.1 서류 종류

| 서류 | 담긴 정보 | 확인 포인트 |
|---|---|---|
| 입찰참가 신청서 | 업체명, 대표자, 사업자번호, 소재지, 제출일 | 마감일 이후 제출? 다른 서류와 정보 불일치? |
| 견적서 | 단가, 수량, 총액, 비고 문구 | 예산 초과? 다른 업체와 문구·금액이 수상하게 동일? |
| 인증서 | 인증 종류, 유효기간, 발급기관 | 필수 인증 누락? 기간 만료? |
| 제품 사양서 | 규격, 재질, 사진 | 공고 요구 사양과 불일치? |
| 업체 현황 | 공장/사무실 유무, 직원 수, 납품 실적, 안전 기록 | 페이퍼컴퍼니(브로커)? 중대재해 이력? |

### 5.2 부적격 사유 목록 (도장 선택지)

| 코드 | 사유 | 연결 정책 |
|---|---|---|
| `OVER_BUDGET` | 예산 초과 | 예산 집행 원칙 |
| `LATE` | 마감 후 제출 | 입찰 절차 |
| `CERT_MISSING` | 필수 인증 누락 | 품질 관리 |
| `CERT_EXPIRED` | 인증 유효기간 만료 | 품질 관리 |
| `SPEC_MISMATCH` | 요구 사양 불일치 | 수요기관 요구 충족 |
| `INFO_MISMATCH` | 서류 간 정보 불일치(사업자번호 등) | 서류 위조 방지 |
| `COLLUSION` | 담합 의심(다른 업체와 견적 동일) | **공정조달** |
| `BROKER` | 실체 없는 업체(브로커) | **공정조달** — 브로커 입찰 근절 |
| `SAFETY` | 중대재해 이력 | **안전** — 중대재해 기업 낙찰 제한 |

- `COLLUSION`은 **두 업체의 서류를 나란히 비교**해야 찾을 수 있다 (이 게임만의 퍼즐 포인트).
- 새 사유는 그 사유가 필요한 사업을 **처음 열 때** 나르미가 소개하고 선택지에 추가된다 ("규칙 추가"를 사업 진행으로 표현). 사업은 순서 자유이므로 어떤 순서로 해도 처음 만날 때 소개된다 (2026-11-08, #59).

### 5.3 나르미 힌트 (확정 — 제안안)

- 사업당 힌트 2회. 누르면 서류의 수상한 부분 한 곳을 형광펜으로 표시하고 한 줄 설명.
- 새 사유가 처음 등장할 때는 나르미가 자동으로 짧게 설명 (교육 효과).

## 6. 낙찰 딜레마 (적격 2곳의 성격 대비)

각 사업은 아래 조합 중 하나를 사용한다. **사용: #2 → #1 → #4 → #5 → #7 (5건, 확정)**

| # | 회사 A | 회사 B | 연결 정책 | 성향 태그 A / B |
|---|---|---|---|---|
| 1 | 최저가 업체 | 조금 비싸지만 튼튼한 업체 | 가격 vs 품질 | `thrift` / `quality` |
| 2 | 실적 많은 대기업 | 실적 없는 혁신 스타트업 | **혁신조달** (정부가 첫 구매자) | `stable` / `innovation` |
| 3 | 효율 좋은 수도권 업체 | 지역 중소기업 | 균형성장, 지역업체 참여 | `thrift` / `coexist` |
| 4 | 저렴한 일반 제품 | 비싼 친환경 인증 제품 | 탄소중립, 녹색조달 | `thrift` / `green` |
| 5 | 납기 빠른 업체 | 사회적기업·장애인 고용 기업 | 사회적 가치 가점 | `stable` / `coexist` |
| 6 | 검증된 기존 시스템 | 새 AI 솔루션 | **AI 조달** | `stable` / `innovation` |
| 7 | 단가 싼 시공사 | 안전 점수 높은 시공사 | 안전, 중대재해 | `thrift` / `safety` |

- 선택한 회사의 성향 태그 점수가 +1 누적된다 → 엔딩 칭호 결정.

## 7. 엔딩

### 7.1 1년 후 조달 뉴스

마지막 사업이 끝나면 신문 지면이 펼쳐진다. 각 사업마다 고른 업체의 결과 헤드라인 1개.

- 예) 스타트업 선택 → "○○초 책상 납품한 스타트업, 1년 만에 해외 수출 성공!" + 작은 기사 "초기 납품 일부 지연, 신속 보완"
- 예) 대기업 선택 → "○○초 책상, 1년간 고장 0건 — 안정적 납품" + 작은 기사 "혁신 스타트업은 다른 판로 찾아"
- 감사 지적이 있었다면 해당 사업에 정정 기사 1개 추가.

### 7.2 칭호 엔딩 (확정 — 제안안)

가장 높은 성향 태그로 결정. 동점이면 "균형 잡힌 조달관".

| 태그 | 칭호 |
|---|---|
| `innovation` | 혁신 개척자 |
| `thrift` | 알뜰 살림꾼 |
| `quality` / `stable` | 믿음직한 조달관 |
| `coexist` | 상생 조달관 |
| `green` | 초록 조달관 |
| `safety` | 안전 지킴이 |
| 지적 0회 보너스 | 칭호 앞에 "완벽한" |

- 엔딩 화면은 캡처·공유하기 좋게 한 장으로 구성 (홍보 활용도).
- 마지막 메시지: "조달은 정답 찾기가 아니라, 무엇을 더 소중히 여길지 고르는 일이에요." (확정)

## 9. 기술 규칙 (반드시 지킬 것)

- **순수 HTML / CSS / JavaScript**. 프레임워크·번들러·빌드 단계 없음.
- `index.html`을 **더블클릭(`file://`)으로 열어도 동작**해야 한다. 따라서:
  - `<script type="module">` 사용 금지 (file://에서 CORS로 막힘). 일반 `<script src>`로 순서대로 로드하고 전역 네임스페이스 하나(`window.Game`)만 쓴다.
  - `fetch()`로 로컬 JSON 읽기 금지. 데이터는 `js/data.js`에서 전역 변수로 정의한다.
- 외부 CDN·인터넷 연결 없이 동작 (폰트·이미지·소리 모두 로컬 파일).
- 입력은 **Pointer Events**로 처리해 마우스와 터치를 같이 지원.
- 저장이 필요하면 `localStorage`를 쓰되 반드시 `try/catch`로 감싸고, 실패해도 게임이 진행돼야 한다.
- **시나리오 데이터와 엔진 코드를 분리**한다. 사업·업체·서류·뉴스 문구는 전부 `js/data.js`에 있고, 엔진 코드에 하드코딩하지 않는다.
- 브라우저: 최신 Chrome / Edge / Safari(iOS).
